## 🔧 工作流程

### 步骤1: 准备阶段
1. **检查PDF存在性**: 使用Bash工具确认文件路径
2. **获取PDF元数据**: 使用mdls获取页数
3. **创建目录结构**:
   ```
   课件详解/[教师名]/[XX-课件名]/
   ├── 00-导航.md
   ├── README.md
   ├── 01-章节1.md
   ├── 02-章节2.md
   └── ...
   ```

### 步骤2: 提取PDF内容 (文本 + 图像)

#### 2.1 提取文本内容
使用pdftotext批量提取：
```bash
/opt/homebrew/bin/pdftotext -f 1 -l 10 "课件.pdf" -
/opt/homebrew/bin/pdftotext -f 11 -l 20 "课件.pdf" -
...
```

**注意**: 每次提取10-20页，避免输出过长。

#### 2.2 提取关键页面图像 ⭐ NEW
**识别需要图像的页面**:
- 包含UML类图的页面
- 包含复杂图表的页面
- 包含架构图的页面
- "实例说明"和"实例解析"的页面

使用pdftoppm转换为图片：
```bash
# 提取单页为PNG
/opt/homebrew/bin/pdftoppm -png -f [页码] -l [页码] "课件.pdf" "/tmp/page-[页码]"

# 批量提取多个关键页
for page in 15 20 27 37 43 50 57; do
  pdftoppm -png -f $page -l $page "课件.pdf" "/tmp/page-$page"
done
```

#### 2.3 分析图像内容
使用Read工具读取生成的PNG图像：
```bash
Read tool: /tmp/page-19-19.png
```

**从图像中提取**:
- UML类图的类名、属性、方法
- 类之间的关系 (关联、继承、实现、依赖)
- 图表的结构和数据
- 文字说明和标注

### 步骤3: 综合分析
**结合文本 + 图像**:
1. 文本提供：定义、说明文字、大纲
2. 图像提供：UML图、架构图、流程图
3. 综合理解：准确把握课件要传达的设计思想
根据提取的文本，识别：
- 章节标题 (通常是大字体或标题格式)
- 页码分布
- 逻辑分段

**识别规则**:
- 相同主题的页面归为一章
- 每章10-20页为宜
- 案例分析可单独成章

### 步骤4: 撰写README总览
包含以下部分：
- 基本信息 (讲师/页数/主题/难度)
- 内容大纲表格
- 核心知识点列表
- 重点页面速查
- 适合场景
- 前置知识
- 相关资源
- 学习建议
- 考试重点
- 学习进度追踪清单

### 步骤5: 撰写逐页详解
对于每一页，按照以下模板：

```markdown
## 📄 第X页 - [页面标题]

### 页面内容
[完整描述这一页的文字内容、图表、代码]

### 重点解析
- **概念1**: [详细解释]
- **概念2**: [详细解释]

### 示例代码 (如适用)
[提取代码并添加中文注释]

### 关键图表 (如适用)
[用ASCII或文字描述图表]

### 考点提示
⚠️ [这页可能的考点]

### 易混淆点
💡 [容易理解错误的地方]

### 相关原则/模式 (如适用)
[与其他知识点的联系]
```

### 步骤6: 创建导航文件
00-导航.md文件，包含：
- 所有章节的链接
- 阅读进度追踪
- 快速查找表

## 📝 注意事项

### 术语一致性
- 设计原则: 使用中文名 + 英文缩写 (如"单一职责原则 SRP")
- 设计模式: 使用中文名 + 英文全称 (如"策略模式 Strategy Pattern")
- 人名: 中英文都保留 (如"Robert C. Martin (Uncle Bob)")

### 代码示例
- 使用Java作为示例语言 (与课件保持一致)
- 添加详细的中文注释
- 提供重构前后的对比代码

### 考点标注
- 使用⚠️标记考点
- 使用💡标记易混淆点
- 使用⭐标记重要程度

### 学术诚信
- 详解文档是辅助学习工具
- 不是简单的PDF文本复制
- 加入了大量的解释、代码、示例
- 用于理解而非替代课件学习
