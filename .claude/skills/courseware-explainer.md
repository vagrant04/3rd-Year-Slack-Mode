## 🔧 工作流程 (改进版)

### 步骤1: 准备阶段
1. **检查PDF存在性**: 使用Bash工具确认文件路径
2. **获取PDF元数据**: 使用mdls获取页数
3. **创建目录结构**:
   ```
   课件详解/[教师名]/[XX-课件名]/
   ├── 00-导航.md
   ├── README.md
   ├── 01-章节1.md
   ├── 02-章节2.md
   └── ...
   ```

### 步骤2: 全局扫描 - 识别需要图像分析的页面 ⭐ 关键步骤

**核心原则**: 在撰写详解之前，必须先识别所有需要图像分析的页面。

#### 方法1: 文本密度分析（主要方法）
```bash
# 逐页提取文本并统计字符数
for i in {1..59}; do
  text=$(/opt/homebrew/bin/pdftotext -f $i -l $i "课件.pdf" -)
  chars=$(echo "$text" | wc -m | tr -d ' ')
  echo "$i,$chars"
done > page_density.csv

# 分析结果: 字符数 < 500的页面很可能是图为主
# 标记这些页面为"需要图像分析"
```

**判断标准**:
- 字符数 < 300: 几乎肯定是图为主 → 必须提取图像
- 字符数 300-600: 可能有重要图表 → 建议提取图像
- 字符数 > 600: 以文字为主 → 文本分析即可

#### 方法2: 关键词识别（辅助方法）
```bash
# 提取全文并标注页码
/opt/homebrew/bin/pdftotext -f 1 -l 59 "课件.pdf" full_text.txt

# 搜索关键词并记录页码（需要手工对照行数推算页码）
grep -n "实例说明\|实例解析\|类图\|UML\|结构图\|架构图" full_text.txt
```

**关键词列表**:
- "实例说明" - 通常有原始设计UML图
- "实例解析" - 可能有重构后UML图或仅文字
- "类图" / "UML" - 明确提到图
- "结构图" / "架构图" - 明确提到图

#### 方法3: 缩略图全览（最可靠，但耗时）
```bash
# 提取所有页面为低分辨率图像（400px宽，快速预览）
/opt/homebrew/bin/pdftoppm -png -scale-to 400 -f 1 -l 59 "课件.pdf" "/tmp/preview/page"

# 使用Read工具快速浏览前几页，识别图像密集区域
# 然后对这些区域提取高分辨率图像
```

**优点**: 100%准确识别所有图表
**缺点**: 需要逐页浏览，耗时较长

#### 方法4: 询问用户（最直接）
在开始详细解析前，询问用户：
```
"我准备解析这个课件，为了确保准确理解UML类图和重要图表，
请问你看过PDF后，觉得哪些页面有重要的图形需要我特别分析？
如果不确定，我可以用文本密度分析自动识别。"
```

### 步骤3: 批量提取确定的关键页面图像

根据步骤2的识别结果，批量提取图像：
```bash
# 假设识别出第5,12,19,27,35,42页需要图像分析
pages=(5 12 19 27 35 42)

for page in "${pages[@]}"; do
  /opt/homebrew/bin/pdftoppm -png -f $page -l $page \
    "课件.pdf" "/tmp/page-$page"
  echo "已提取第${page}页图像: /tmp/page-${page}-${page}.png"
done
```

### 步骤4: 提取全文文本内容

使用pdftotext批量提取所有文本：
```bash
/opt/homebrew/bin/pdftotext -f 1 -l 20 "课件.pdf" -
/opt/homebrew/bin/pdftotext -f 21 -l 40 "课件.pdf" -
/opt/homebrew/bin/pdftotext -f 41 -l 59 "课件.pdf" -
```

**注意**: 每次提取10-20页，避免输出过长。

### 步骤5: 逐页分析（文本 + 图像结合）

**对于有图像的页面**:
1. 先用Read工具读取图像: `Read tool: /tmp/page-19-19.png`
2. 分析UML图的结构:
   - 类名、属性、方法
   - 类之间的关系 (关联→、继承△、实现△、依赖--→、组合◆→)
   - 红框/高亮标注的问题点
3. 再阅读该页的文本内容
4. 综合图像+文本，准确理解设计意图

**对于无图像的页面**:
1. 直接阅读文本内容
2. 理解概念定义和说明
3. 撰写详解

### 步骤6: 章节划分与结构分析

根据提取的文本和图像，识别：
- 章节标题 (通常是大字体或标题格式)
- 页码分布
- 逻辑分段

**识别规则**:
- 相同主题的页面归为一章
- 每章5-15页为宜
- 有完整UML案例的独立成章

### 步骤7: 撰写README总览
包含以下部分：
- 基本信息 (讲师/页数/主题/难度)
- 内容大纲表格
- 核心知识点列表
- 重点页面速查
- 适合场景
- 前置知识
- 相关资源
- 学习建议
- 考试重点
- 学习进度追踪清单

### 步骤8: 撰写逐页详解

**关键原则**: 图像优先，确保准确

**对于包含UML图的页面**:
1. **必须先Read图像**，理解UML结构
2. 在文档中绘制ASCII版UML图或表格
3. 详细说明类关系类型（关联/继承/实现/组合等）
4. 代码示例必须与UML图完全对应
5. 特别标注红框/高亮标注的问题点

**对于纯文本页面**:
按照以下模板：

```markdown
## 📄 第X页 - [页面标题]

### 页面内容
[完整描述这一页的文字内容、图表、代码]

### 重点解析
- **概念1**: [详细解释]
- **概念2**: [详细解释]

### 示例代码 (如适用)
[提取代码并添加中文注释]

### 关键图表 (如适用)
[用ASCII或文字描述图表]

### 考点提示
⚠️ [这页可能的考点]

### 易混淆点
💡 [容易理解错误的地方]

### 相关原则/模式 (如适用)
[与其他知识点的联系]
```

### 步骤9: 创建导航文件
00-导航.md文件，包含：
- 所有章节的链接
- 阅读进度追踪
- 快速查找表

### 步骤10: 质量验证 ⭐ 新增
在完成所有文档后，进行质量检查：
1. **UML图准确性检查**: 对照图像，验证ASCII图和代码是否一致
2. **文本完整性检查**: 确保每一页都有解释
3. **交叉引用检查**: 确保章节间链接正确
4. **格式一致性检查**: 确保emoji、标题层级统一

## 📝 注意事项

### 术语一致性
- 设计原则: 使用中文名 + 英文缩写 (如"单一职责原则 SRP")
- 设计模式: 使用中文名 + 英文全称 (如"策略模式 Strategy Pattern")
- 人名: 中英文都保留 (如"Robert C. Martin (Uncle Bob)")

### 代码示例
- 使用Java作为示例语言 (与课件保持一致)
- 添加详细的中文注释
- 提供重构前后的对比代码

### 考点标注
- 使用⚠️标记考点
- 使用💡标记易混淆点
- 使用⭐标记重要程度

### 学术诚信
- 详解文档是辅助学习工具
- 不是简单的PDF文本复制
- 加入了大量的解释、代码、示例
- 用于理解而非替代课件学习
