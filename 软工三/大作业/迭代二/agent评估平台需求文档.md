## Agent评估平台 – 详细需求文档 v2.0

### 1. 引言

本平台用于对“旅行规划自治Agent”进行自动化、多维度的评测。支持评测任务的全生命周期管理、多套指标的组合执行，并提供单次结果可视化与多次任务对比分析能力。平台自身为前后端分离的Web应用，通过调用Agent平台暴露的评估接口（`POST /api/eval/run`）获得规划结果和执行轨迹，再在本地完成指标计算。

### 2. 系统概述

#### 2.1 产品定位

一个面向LLM Agent的评测中台，通过对Agent赋予相同的测试输入、记录其完整行为轨迹（Trace），并按需组合效果、效率、安全、推理质量等多类指标，输出结构化评估报告及可视化图表。

#### 2.2 核心特性

- 评测任务全生命周期管理（创建、配置、执行、状态查看、删除）
- 数据集管理（预置旅行规划测试用例集，支持JSON格式上传）
- 支持≥4类评估指标：成功率、工具调用正确率、LLM‑as‑a‑Judge推理质量、响应时间等
- 指标的灵活组合：用户创建任务时可自由勾选需要计算的指标
- 单次评估结果深度透视（指标得分、详细评语、Agent执行日志回放）
- 多任务对比：选择≥2个历史任务，生成雷达图/柱状图，直观对比版本或Prompt差异
- 后端异步执行评测，前端通过轮询/WebSocket获取任务进度

#### 2.3 技术选型建议

| 组件         | 技术建议                                                     |
| ------------ | ------------------------------------------------------------ |
| 前端         | React + Ant Design / Tailwind CSS，图表库：Recharts 或 ECharts |
| 后端         | Python (FastAPI) 或 Node.js (Express)，需支持异步任务        |
| 异步任务队列 | 可选 Celery (Python) 或 Bull (Node)，如并发量不大可用后台线程 |
| 数据存储     | SQLite / PostgreSQL（评测任务、结果），文件系统（数据集JSON） |
| 指标计算库   | Ragas（用于LLM‑as‑a‑Judge）、自定义Python脚本                |
| HTTP客户端   | 调用Agent平台评估接口                                        |

│  └─────────────────────┬───────────────────────┘  │
│                        │                          │
│  ┌─────────────────────┴───────────────────────┐  │
│  │               指标计算器                    │  │
│  │  - 成功率      - 工具正确率                │  │

│  └────────────────────────────────────────────┘  │
└───────────────────────┬──────────────────────────┘
                        │ HTTP
┌───────────────────────┴──────────────────────────┐

**关键交互**：评估平台后端作为客户端，向 Agent 平台发送评测请求。Agent 平台根据接收到的测试输入执行一次完整的规划过程，并将结果和完整 Trace 返回给评估平台。评估平台**不直接访问 Agent 的内部状态或工具**，一切通过标准 HTTP API 完成。

### 4. 功能模块详细需求

#### 4.1 评测任务管理

满足基本约束：前后端分离，支持评测任务的 CRUD 和状态管理。

**4.1.1 任务创建**

- 用户可以创建一个新的评测任务。
- 创建表单需包含以下配置字段：
  - **任务名称**（必填，字符串）
  - **Agent版本标识**（如 `v1.0`, `plan-and-execute`，用于后续对比）
  - **数据集选择**（下拉列表，来源于已上传的数据集）
  - **指标选择**（多选，至少勾选1项）：成功率、工具正确率、LLM‑as‑a‑Judge推理质量、响应时间、Token消耗等
  - **Agent 平台地址**（可配置，默认为 `http://localhost:8000/api/eval/run`）
  - **其他高级配置**（JSON字段，可选，如 model 参数、temperature 等）
- 创建后任务状态为 `pending`，存入数据库。

**4.1.2 任务列表与状态展示**

- 列表页展示所有评测任务，每项显示：名称、Agent版本、数据集名、状态、创建时间、进度（如 `3/10`）。
- 状态生命周期：
  - `pending` → `running` → `done` / `failed`
- 支持分页、搜索。

**4.1.3 任务操作**

- **启动**：手动点击“执行”将任务状态改为 `running`，后端异步队列开始执行。
- **查看结果**：链接到单任务详情页。
- **删除**：可删除已完成或失败的任务，运行中的不可删除。
- **重新运行**：基于原配置一键创建新任务。

#### 4.2 数据集管理

- 系统预置一个旅行规划测试数据集（至少包含10个不同难度的测试用例）。
- 每条测试用例为 JSON 对象：
  ```json
  {
    "id": "case_01",
    "input": "我想从南京去苏州玩2天，预算600元，喜欢园林",
    "expected_constraints": {
      "destination": "苏州",
      "days": 2,
      "budget_limit": 600,
      "must_include_keywords": ["拙政园", "狮子林"]
    },
    "expected_tool_sequence": ["search_attractions", "query_weather", "calculate_distance", "calculate_budget"],
    "difficulty": "easy"
  }
  ```
- 支持用户上传新的数据集文件（JSON 格式），前端提供文本编辑器或文件上传。
- 数据集列表页支持查看用例数量、下载、删除。

#### 4.3 评测执行与指标计算

**执行流程**：
1. 从数据集获取所有用例。
2. 对每个用例：
   a. 构造请求体，调用 Agent 平台 `POST /api/eval/run`。
   b. 获取响应 `{output, trace, metrics_from_agent}`。
   c. 将 `output` 和 `trace` 传入指标计算模块。
3. 汇总所有用例的指标得分，计算平均分。
4. 更新任务状态为 `done`，存储详细结果。

**指标计算详细规则**：

| 指标                        | 计算方法                                                     | 数据来源                           | 类型           |
| --------------------------- | ------------------------------------------------------------ | ---------------------------------- | -------------- |
| **成功率**                  | 检查 Agent 最终输出是否满足 `expected_constraints` 中的全部硬性约束（如目的地正确、天数正确、预算未超）。每个约束通过得 1 分，归一化到 0‑1。 | `output` + `expected_constraints`  | 显式、面向结果 |
| **工具调用正确率**          | 对比实际工具调用序列（从 `trace` 中提取）与 `expected_tool_sequence` 的匹配度，允许顺序容忍（如 A→B→C 与 A→C→B 可能等效），计算调用种类和关键参数的匹配比例。**提取方法**：评估平台从 `trace` 中筛选 `event_type == "tool_call"` 的事件，提取 `data.tool_name` 得到工具调用序列（带时间顺序），与预期的 `expected_tool_sequence` 进行模糊匹配（允许顺序容忍规则）。 | `trace` + `expected_tool_sequence` | 显式、面向过程 |
| **LLM‑as‑a‑Judge 推理质量** | 使用 Ragas 或自定义 Prompt，让裁判模型针对 Agent 的思考链（`trace` 中 thought 部分）和质量（逻辑连贯性、修正合理性）打分（1‑5），再转换为 0‑1。可设计评判维度：计划合理性、工具选择恰当性、自我修正有效性。 | `trace`（thought 部分）            | 模糊、面向过程 |
| **响应时间**                | 计算 Agent 从开始到返回 output 的总耗时（可直接从 Agent 返回的 `metrics.elapsed_time` 获取）。若缺失，可由调用前后的时间戳计算。 | 调用接口耗时或 Agent 返回字段      | 显式、面向性能 |
| **Token 消耗**（扩展）      | 统计 Agent 执行过程中消耗的总 token 数，可要求 Agent 平台返回 `token_usage`。 | Agent 平台返回                     | 显式、面向性能 |
| **安全/幻觉检查**（扩展）   | 使用简单规则或 LLM 判断输出是否包含危险建议或明显编造的信息。 | `output`                           | 模糊、面向安全 |

**指标组合策略**：用户创建任务时勾选的指标构成一个“评估策略”。引擎动态调用对应的计算函数，并获得加权总分（默认各指标等权，可配置权重）。

#### 4.4 结果展示与对比

**4.4.1 单次任务详情页**

- 顶部：任务元信息（名称、Agent版本、数据集、执行时间）
- 总体得分卡片：综合得分（可加权）、各指标得分条形图。
- 每个指标展开区：
  - 成功率：展示通过/失败用例列表，每个用例的约束检查明细。
  - 工具正确率：展示工具调用序列对比表，标注错误步骤。
  - 推理质量：展示裁判评语（LLM 给出的文字评价）及分数分布。
  - 响应时间：展示平均及最慢用例的时间柱状图。
- **Agent 执行日志回放**：选择某个用例，可以逐步骤查看 Agent 的 `trace`（思考、工具调用、观察、修正），类似调试器的单步执行视图。

**4.4.2 多任务对比页**

- 用户勾选≥2个历史任务，进入对比视图。
- 支持的图表：
  - **雷达图**：各指标平均分对比。
  - **分组柱状图**：单指标直接比较。
  - **汇总表格**：列出每个任务的各指标得分、综合得分。
- 用于对比不同 Agent 版本、不同 Prompt 或不同模型的效果。

### 5. 接口规范（评估平台后端 API）

所有 API 路由以 `/api/v1` 为前缀。

#### 5.1 数据集管理

| 方法   | 路径             | 描述           | 请求体                              | 响应                                    |
| ------ | ---------------- | -------------- | ----------------------------------- | --------------------------------------- |
| GET    | `/datasets`      | 获取数据集列表 | -                                   | `[{id, name, description, case_count}]` |
| GET    | `/datasets/{id}` | 获取数据集详情 | -                                   | `{id, name, cases: [...]}`              |
| POST   | `/datasets`      | 上传新数据集   | `{name, description, cases: [...]}` | `{id, name}`                            |
| DELETE | `/datasets/{id}` | 删除数据集     | -                                   | `{success}`                             |

#### 5.2 评测任务管理

| 方法   | 路径                  | 描述     | 请求体            | 响应                         |
| ------ | --------------------- | -------- | ----------------- | ---------------------------- |
| GET    | `/tasks`              | 任务列表 | `?page=1&size=10` | `{items:[...], total}`       |
| POST   | `/tasks`              | 创建任务 | 见任务配置对象    | `{task_id, status}`          |
| GET    | `/tasks/{id}`         | 任务详情 | -                 | 任务对象 + result (若已完成) |
| DELETE | `/tasks/{id}`         | 删除任务 | -                 | `{success}`                  |
| POST   | `/tasks/{id}/execute` | 启动任务 | -                 | `{status: "running"}`        |

**任务配置对象示例**：
```json
{
  "name": "V1 基线评测",
  "agent_version": "1.0.0",
  "dataset_id": "ds_001",
  "metrics": ["success_rate", "tool_accuracy", "llm_judge", "response_time"],
  "agent_endpoint": "http://localhost:8000/api/eval/run",
  "weight_config": {
    "success_rate": 0.4,
    "tool_accuracy": 0.3,
    "llm_judge": 0.2,
    "response_time": 0.1
  }
}
```

#### 5.3 评测结果

| 方法 | 路径                         | 描述                   | 响应                                      |
| ---- | ---------------------------- | ---------------------- | ----------------------------------------- |
| GET  | `/tasks/{id}/result`         | 获取任务的完整评估结果 | 包含汇总指标、每个用例的详细得分、trace等 |
| GET  | `/tasks/{id}/result/summary` | 仅汇总指标             | `{overall_score, metrics: {...}}`         |

#### 5.4 对比分析

| 方法 | 路径                        | 描述                 | 请求体                        | 响应                                        |
| ---- | --------------------------- | -------------------- | ----------------------------- | ------------------------------------------- |
| POST | `/compare`                  | 提交对比请求         | `{"task_ids": ["id1","id2"]}` | `{tasks: [...], metrics_comparison: {...}}` |
| GET  | `/compare/data?ids=id1,id2` | 获取对比数据（简化） | -                             | 同上                                        |

#### 5.5 WebSocket（可选）

评估平台自身可提供 `ws://<host>/ws/tasks/{task_id}` 用于推送任务进度（**注意：此为评估平台自己的 WebSocket，与 Agent 平台的 WebSocket (`ws://<host>/ws/{session_id})` 互不干扰**）：
- 推送消息：
  ```json
  {
    "type": "progress",
    "data": {
      "current_case": 3,
      "total_cases": 10,
      "status": "running"
    }
  }
  ```

### 7. 与 Agent 平台的集成约定

- 评估平台通过 `agent_endpoint` 配置项动态指向 Agent 平台。默认值 `http://127.0.0.1:8000/api/eval/run`。
- 请求格式：
  ```json
  POST /api/eval/run
  {
    "input": "用户需求文本",
    "session_config": {}
  }
  ```
- Agent 平台响应格式（双方必须遵守）：
  ```json
  {
    "output": {
      "itinerary": { ... },
      "final_response": "..."
    },
    "trace": [
      {
        "timestamp": "...",
        "event_type": "thought",
        "data": { "content": "..." }
      },
      {
        "timestamp": "...",
        "event_type": "tool_call",
        "data": { "tool_name": "...", "params": {...}, "duration_ms": 123 }
      },
      {
        "timestamp": "...",
        "event_type": "observation",
        "data": { "tool_name": "...", "result_summary": "..." }
      }
    ],
    "metrics": {
      "elapsed_time_seconds": 34.5,
      "total_tokens": 1234
    }
  }
  ```
- 若 Agent 平台返回错误（如超时），评估平台应将用例标记为失败并记录错误信息，但不应中断整个评测任务。

### 8. 前端界面要求

- **任务管理**：列表页提供表格、状态标签、操作按钮（执行、查看、删除、重新运行）。
- **创建任务**：表单页包含数据集下拉选择、指标多选按钮组、Agent端点输入框等，并做前端校验。
- **结果详情**：
  - 使用卡片布局展示总体分数和时间。
  - 指标细节用折叠面板（Accordion）展示，成功率展示通过/失败矩阵。
  - 日志回放区：时间轴组件，可展开每个Trace事件的详细JSON。
- **对比视图**：采用顶部选择任务的多选框，下方动态渲染雷达图或柱状图。
- **响应式**：保证在桌面端使用流畅。

### 9. 非功能性需求

| 需求         | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| **安全性**   | 无用户认证要求（课程项目），但需防止恶意任务导致后端阻塞（限制并发执行数≤3）。 |
| **可靠性**   | 单个测试用例失败不影响其他用例；评测超时控制（单用例最长 120 秒）。 |
| **性能**     | 10个用例的评测任务应在 10 分钟内完成（取决于Agent平台响应速度）。 |
| **可扩展性** | 新增指标只需添加一个计算函数并注册到指标工厂中，无需修改核心引擎。 |
| **日志**     | 后端打印每个步骤的简要日志，方便调试。                       |
| **文档**     | 提交 README 说明如何启动评估平台、配置数据集、运行评测。     |
