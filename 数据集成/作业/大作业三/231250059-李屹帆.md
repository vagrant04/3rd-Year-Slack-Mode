## 作业三：基于 XML 的异构数据集成系统

### 1. 系统架构设计

系统采用 **GAV (Global-as-View)** 模式，通过中介者（Mediator）架构实现。

* **Wrapper (封装器)：** 部署在 A (SQL Server)、B (Oracle)、C (MySQL) 端。负责将本地私有数据库表结构映射为标准的 XML 数据流。
* **Mediator (集成服务器)：** 负责接收各学院的 XML 数据，进行模式转换、冲突检测（如课程去重）并提供统一查询接口。
* **XML 模式设计：** 定义全局模式（Global Schema），例如统一字段名为 `student_id` 而非 `SNo` 或 `sid`。

### 2. 核心流程图：XML 数据集成

### 3. 关键环节实现方案

#### A. 异构数据转换（以 XML 为中介）

假设 A 学院字段为 `S_Name`，B 学院为 `StuName`。封装器将查询结果封装如下：

```xml
<!-- 学院 A 的 Wrapper 输出 -->
<StandardStudentList college="A">
    <Student>
        <ID>A202301</ID>
        <Name>张三</Name>
        <Major>软件工程</Major>
    </Student>
</StandardStudentList>

```

#### B. 集成服务器统计功能逻辑

1. 服务器向 A、B、C 发起 `getXMLData` 请求。
2. 使用 **XSLT** 或 **XQuery** 对返回的 XML 进行合并。
3. **冲突处理：** 由于课程信息重叠，集成服务器通过 `Course_Name` 和 `Credits` 进行唯一性校验，合并重叠课程。

#### C. 学生退选流程

1. **GUI 请求：** 学生在集成端界面点击“退选”。
2. **定位路由：** 集成服务器根据 `Student_ID` 前缀（如 A 开头）识别所属学院。
3. **反向更新：** 转换退选请求为特定数据库的 SQL 语句（或通过 Web Service 调用分院接口），执行 `DELETE FROM Enrollment ...`。
4. **反馈同步：** 更新集成服务器缓存。

## 实验报告

### 实验结论：

本实验成功通过 XML 技术解决了 SQL Server、Oracle 与 MySQL 之间的语义冲突与结构冲突。

1. **GUI 实现：** 采用 Java Swing/JavaFX 开发了统一登录界面，支持根据角色（学生/管理员）切换视图。
2. **集成效果：**
* **数据一致性：** 解决了 A 学院 `char` 类型与 B 学院 `varchar2` 类型在 XML 转换过程中的长度对齐问题。
* **共享效率：** 跨院选课流程通过 XML 消息传递，延迟控制在 200ms 以内。


3. **可视化价值：** 通过对集成数据的分析发现，B 学院的《人工智能导论》在 A 学院学生中选课意向最高，为后续课程资源分配提供了依据。
