## 1. 云计算概念

| 重点 | 解答 | 来源 |
| --- | --- | --- |
| 什么是云计算？ | 云计算没有唯一权威定义。可概括为：通过网络按需向用户提供可动态伸缩、可计量、可共享的 IT 资源与服务，包括计算、存储、网络、平台和软件等。它本质上是增强版效用计算与更广泛服务计算的结合，即不仅按量计费，还强调 IT 资源管理、服务化交付和弹性扩展。 | `1-云计算概念-2026.pdf` p11, p23 |
| 云计算的基本术语 | 云是一个独特的 IT 环境；IT 资源是云计算的最小构成单元，包括计算、存储、平台、应用等资源；云服务是将具备可扩展性的 IT 资源封装后交付给用户的形式。 | `1-云计算概念-2026.pdf` p8-p10 |
| 云计算的特征 | 五个核心特征是按需自助服务、广泛的网络访问、资源池化、快速弹性、可计量服务。理解时可抓住一句话：用户通过网络自助申请资源，云平台从资源池中动态分配，能快速扩缩，并按使用量计量。 | `1-云计算概念-2026.pdf` p27 |
| 部署模型 | 公有云由第三方云提供者拥有并向公众开放；私有云由单一组织拥有并服务于组织内部；混合云由两种或更多部署模型组合而成；社区云类似公有云，但访问限定于特定用户社区。扩展模型还包括边缘云、分布式云、专属云。 | `1-云计算概念-2026.pdf` p28 |
| 服务模型 | SaaS 是软件作为服务，用户直接使用云上应用；PaaS 是平台作为服务，提供应用开发、运行环境和平台能力；IaaS 是基础设施作为服务，提供虚拟机、存储、网络等基础资源。三者可理解为：SaaS 面向最终用户，PaaS 面向开发者，IaaS 面向需要基础资源控制权的用户。 | `1-云计算概念-2026.pdf` p29-p32 |
| IaaS | IaaS 通过虚拟机方式对外提供计算、存储和网络能力，用户自行安装操作系统、配置公网 IP、挂载存储，并解决多台机器之间的协同问题。优势是资源可动态申请和释放、按使用量计费、资源利用率更高。 | `1-云计算概念-2026.pdf` p30 |
| PaaS | PaaS 提供应用开发和运行环境，包括 API、运行平台、数据库、文件系统、应用运行环境等逻辑资源。它替用户处理资源动态扩展和容错管理，但用户自主权下降，需要按平台给定的编程环境和模型构建应用。 | `1-云计算概念-2026.pdf` p31 |
| SaaS | SaaS 通过浏览器或客户端访问云上的应用，用户通常不关心底层基础设施和运行平台，只消费应用功能。 | `1-云计算概念-2026.pdf` p32 |
| 云计算三元认知论 | 云计算可从三层理解：第一，它是一种商业模式，按需提供基础设施、平台和软件服务；第二，它是一种计算范式，关注云体、云栈等逻辑结构和实现方式；第三，它是一种实现技术集合，包括虚拟化、分布式计算、分布式存储、自动化运维等。 | `1-云计算概念-2026.pdf` p36-p37 |
| 云计算开源方法论 | 云计算时代的开源不仅是开放源代码产品，更是构造大规模复杂软件的协作方法。它通过开放许可证、源代码可学习修改分发、社区协作等方式促进技术创新、自主可控、产业发展和研发能力提升。 | `1-云计算概念-2026.pdf` p38-p40 |

## 2. 云计算架构

| 重点 | 解答 | 来源 |
| --- | --- | --- |
| SOA 与微服务架构 | SOA 将应用的功能单元抽象为服务，通过定义良好的接口和契约互联，强调服务复用和业务弹性。微服务是在 SOA 思想上进一步组件化、服务化，把单体业务拆成多个可独立开发、运行和部署的小应用。简记：SOA 偏企业级服务集成，微服务偏业务组件自治。 | `2-云计算架构-2026.pdf` p8-p12 |
| 微服务架构 | 微服务是一种松耦合、可独立开发和部署的架构风格，每个服务只做一件事，通常无状态、可独立扩展、升级和替换。优势是独立部署、故障隔离、技术栈灵活、弹性伸缩；挑战是分布式复杂性、服务治理、跨服务一致性和接口契约管理。 | `12-云原生.pdf` p12; `12-云原生案例.pdf` p4 |
| 云计算二维视角 | 最易理解的二维视角是“基础架构 + 应用程序”，也可理解为后端 + 前端。基础架构进一步包含虚拟化层、Web 服务层、服务总线层和用户界面等；云应用则由应用本身、应用实例、服务和云命令行界面组成。 | `2-云计算架构-2026.pdf` p14-p18 |
| 云计算逻辑架构 | 云计算逻辑架构包括云栈、云体、技术体系结构等。云栈从纵向分层看云平台，云体从横向资源集合看云计算的物质基础，技术体系结构说明如何实现资源池、管理中间件、SOA 构建层等能力。 | `2-云计算架构-2026.pdf` p20-p26 |
| 云栈是什么？ | 云栈又称云平台，是云上应用的运行环境，支持应用发布、运行、监控、调度、伸缩，并提供访问控制、权限管理等辅助机制。云栈通常按层组织，常见三层是 IaaS、PaaS、SaaS。 | `2-云计算架构-2026.pdf` p20-p24 |
| 云体是什么？ | 云体是云计算的物质基础，是云计算使用的资源集合和软硬件环境，包括网络、服务器、存储器、交换机，以及广义上的电力、空调、机架等数据中心辅助设施。 | `2-云计算架构-2026.pdf` p20, p30-p33 |
| 云计算技术体系结构 | 技术体系结构可分为物理资源层、资源池层、管理中间件层、SOA 构建层。物理资源层提供计算机、存储、网络等设备；资源池层将大量资源组织成同构或近似同构资源；管理中间件层调度任务和管理资源；SOA 构建层把云能力封装成标准服务。 | `2-云计算架构-2026.pdf` p25-p26 |

## 3. 分布式计算与分布式存储

| 重点 | 解答 | 来源 |
| --- | --- | --- |
| 分布式计算是什么？ | 分布式计算是多个通过网络互联的计算节点共同完成任务：把大问题拆成小任务，分配给不同节点处理，再合并结果。难点在于任务划分、多节点通信、数据一致性、故障处理和资源调度。 | `4-分布式计算-2026.pdf` p3-p7 |
| CAP 理论 | CAP 指一致性、可用性、分区容错性。分布式系统最多同时满足其中两项。由于网络分区在大规模分布式系统中不可避免，实际系统通常在 CP 与 AP 之间取舍：CP 偏一致但可能牺牲部分可用性，AP 偏高可用但允许短期不一致。 | `4-分布式计算-2026.pdf` p8-p10 |
| BASE 理论 | BASE 追求最终一致性，包括基本可用、软状态、最终一致性。它常用于高可用互联网系统：系统故障时允许部分能力降级，允许中间状态存在，只要经过一段时间后数据副本最终一致即可。 | `4-分布式计算-2026.pdf` p10 |
| 一致性 Hash 算法 | 普通 Hash 的问题是 `Hash(Key) mod N` 与节点数 N 强相关，节点增删会导致大量 Key 重新映射。一致性 Hash 把 Key 和节点映射到同一个环上，节点变化时只影响环上相邻区间的数据迁移，降低扩缩容代价，常用于缓存、分布式键值系统和 Cassandra/Swift 等存储寻址。 | `4-分布式计算-2026.pdf` p19-p21; `5-分布式存储-2026.pdf` p3, p38; `10-OpenStack-2026.pdf` p37 |
| Hadoop MapReduce 思想 | MapReduce 的核心是“移动计算比移动数据更划算”：数据分块存储在多台机器上，Map 阶段尽量在数据所在节点本地处理，产生中间键值对，Reduce 阶段按 Key 汇总合并结果。Hadoop 由 HDFS、Yarn、MapReduce、Common 等组成，适合海量数据的批处理。 | `4-分布式计算-2026.pdf` p30-p41 |
| Spark RDD 思想 | Spark 专注于数据计算，常与 HDFS 等存储系统配合。RDD 是弹性分布式数据集，强调内存计算、DAG 调度和容错血缘关系，相比传统 MapReduce 更适合迭代计算、交互式分析和机器学习场景。 | `4-分布式计算-2026.pdf` p50-p52 |
| Hadoop 生态 | Hadoop 生态包括 HDFS、Yarn、MapReduce，以及 Zookeeper、HBase、Pig、Hive、Flume 等组件。Zookeeper 提供分布式协调；HBase 是分布式数据库；Pig/Hive 提供高层数据处理抽象；Flume 用于日志等数据传输。 | `4-分布式计算-2026.pdf` p41-p48 |
| Spark 生态 | Spark 是大数据计算处理框架，强调批处理、DAG、内存计算，并包含 MLlib 等组件，常位于大数据分析软件栈的计算层，底层数据存储通常仍由 HDFS 等系统承担。 | `4-分布式计算-2026.pdf` p50-p52 |
| 分布式存储系统 | 分布式存储是对单机存储的扩展，核心问题是数据如何均匀分布到多个节点、如何用多副本保证可用性和一致性、如何检测并处理节点故障。常见类型包括分布式文件系统、分布式键值系统、分布式表、分布式数据库。 | `5-分布式存储-2026.pdf` p3-p5 |
| 区块链概念 | 区块链是共享、不可篡改、去中心化的分布式账本，结合分布式数据存储、点对点传输、共识机制和加密算法。每个区块包含前一区块哈希、时间戳和交易数据，借助链式结构和共识机制保证难以篡改。缺点是存储和计算开销大。 | `5-分布式存储-2026.pdf` p7-p13 |

## 4. 虚拟化技术

| 重点 | 解答 | 来源 |
| --- | --- | --- |
| Type 1 与 Type 2 硬件虚拟化 | Type 1 裸机虚拟化直接在物理硬件上运行 Hypervisor，例如服务器上使用 vSphere 管理虚拟机；Type 2 寄居虚拟化在宿主操作系统上运行虚拟化软件，例如笔记本上用 VirtualBox。Type 1 性能和隔离通常更好，Type 2 更适合个人开发测试。 | `6-虚拟化技术-2026.pdf` p7-p8 |
| 硬件级虚拟化 | 硬件级虚拟化在硬件与客户操作系统之间加入 VMM/Hypervisor，虚拟化 CPU、内存、I/O、网络等资源，使多个客户操作系统隔离运行。它要求同质、高效、资源受控。 | `6-虚拟化技术-2026.pdf` p7-p12 |
| 基于软件的完全虚拟化 | VMM 完全掌控底层硬件与客户操作系统，客户操作系统不知道自己运行在虚拟环境中。CPU 虚拟化可通过解释执行、扫描与修补、二进制翻译等方式实现，但性能开销较大。 | `6-虚拟化技术-2026.pdf` p13-p14 |
| 基于硬件辅助的虚拟化 | 在硬件中加入虚拟化支持，例如根/非根操作模式、VMCS、扩展页表等，让硬件参与虚拟机创建、调度、运行和退出，降低 VMM 实现难度并提升性能。 | `6-虚拟化技术-2026.pdf` p15, p19-p20 |
| 改操作系统的类虚拟化 | 类虚拟化又称半虚拟化，需要修改客户操作系统，使其知道自己运行在虚拟环境中，并通过超级调用与 VMM 协作。优点是减少地址空间切换、跨特权级切换和内存复制，提升性能，也让 VMM 更了解客户机内部状态。 | `6-虚拟化技术-2026.pdf` p16-p17 |
| 操作系统级虚拟化 | 操作系统级虚拟化没有传统 Hypervisor/VMM，而是在同一个宿主操作系统内核中运行多个隔离执行环境，也就是容器。它共享宿主内核，因此启动快、资源占用低，但隔离性弱于虚拟机，并且通常要求相同内核。 | `6-虚拟化技术-2026.pdf` p21-p24 |
| VMware | VMware 是虚拟化技术和公司名称，1999 年推出 x86 虚拟化产品。vSphere 可安装在裸机服务器上同时运行多台虚拟机，Workstation 则运行在 Windows/Linux 上模拟 x86 PC 环境。 | `6-虚拟化技术-2026.pdf` p27-p28 |
| Xen | Xen 是剑桥大学开发的开源虚拟机监视器，支持半虚拟化和完全虚拟化。半虚拟化需要修改操作系统但不修改应用，完全虚拟化让客户机感觉自己直接运行在硬件上。Xen 支持虚拟机实时迁移。 | `6-虚拟化技术-2026.pdf` p28-p29 |
| KVM | KVM 是 Linux 生态中的虚拟化机制，2006 年由 Qumranet 宣布诞生，后来在 Red Hat 等推动下成为重要的服务器虚拟化技术路线。 | `6-虚拟化技术-2026.pdf` p27, p30 |

## 5. 容器技术

| 重点 | 解答 | 来源 |
| --- | --- | --- |
| 虚拟机 vs 容器 | 虚拟机是硬件级虚拟化，每个 VM 有独立操作系统，隔离强但启动慢、资源占用高、镜像大。容器是操作系统级虚拟化，共享宿主机内核，做进程级隔离，启动快、资源占用低、镜像小，但隔离性依赖内核机制。 | `7-容器技术-2026.pdf` p3-p6; `6-虚拟化技术-2026.pdf` p21-p22 |
| Namespace | Namespace 通过改变进程对系统资源的可见性实现环境隔离，让容器内进程看不到或无法访问宿主机和其他容器资源。常见类型包括 PID、User、Mount、IPC、UTS、Network。 | `7-容器技术-2026.pdf` p9-p10 |
| Cgroup | Cgroup 用于资源隔离和限制，允许创建进程控制组，并限制、记录、隔离 CPU、内存、I/O 等物理资源使用。它解决的是“用多少”的问题，保证资源有限时应用稳定运行。 | `7-容器技术-2026.pdf` p8-p10 |
| Docker | Docker 是推动容器技术普及的容器引擎，核心组件包括 Docker Daemon、Docker Client 和 Registry。核心技术是基于 namespace/cgroup 的隔离，以及基于写时复制的镜像技术。 | `7-容器技术-2026.pdf` p14-p15 |
| Docker 镜像 | 镜像是只读的容器模板，包含运行应用所需的文件系统、库、配置和元数据。它具有不可修改、分层存储、版本控制等特点，可通过 Dockerfile 声明式构建。 | `7-容器技术-2026.pdf` p16-p20 |
| Docker 镜像分层存储 | 镜像由多个只读文件系统层组成，不同镜像可以共享相同层，从而节省存储、加快拉取。扩展镜像时，从已有镜像逐步构建，每一步形成一个 Layer。 | `7-容器技术-2026.pdf` p19-p21 |
| 写时复制机制 | Docker 镜像的具体实现依赖 Copy On Write 与 UnionFS。多个容器共享镜像的只读层，每个容器有独立可写容器层；只有发生写入时才在容器层记录变更，因此既节省空间又保持容器间独立。 | `7-容器技术-2026.pdf` p21-p24 |
| 容器编排 | 容器编排是对大量容器进行自动化集中管理和调度的技术。基本流程是：开发者用 JSON/YAML 定义目标状态，编排工具选择最优主机并部署容器，再管理生命周期、健康检查、重启、迁移、滚动更新、扩缩容、负载均衡和资源分配。 | `7-容器技术-2026.pdf` p26-p34 |
| Kubernetes/K8S | Kubernetes 是开源的容器编排平台，用于自动部署、扩缩和管理容器化应用。它采用声明式目标状态，控制器持续把当前状态驱动到期望状态。核心能力包括自动上线和回滚、服务发现与负载均衡、自我修复、存储编排、水平扩缩、Secret/配置管理等。 | `7-容器技术-2026.pdf` p36-p40 |
| Pod | Pod 是 K8S 中创建和管理的最小可部署计算单元，包含一个或多个紧密耦合的容器，共享 Linux Namespace、cgroup、文件系统卷和网络。 | `7-容器技术-2026.pdf` p40 |

## 6. 云计算网络与云数据中心

| 重点 | 解答 | 来源 |
| --- | --- | --- |
| 软件定义网络 SDN | SDN 的核心思想是控制转发分离和可编程性。传统网络设备把控制面和数据面耦合在一起，难以统一管理；SDN 通过集中控制器管理交换机转发表，使网络像软件一样可配置、可编程。 | `8-云计算网络-2026.pdf` p40-p43 |
| OpenFlow | OpenFlow 是早期 SDN 的关键成果。OpenFlow Switch 将控制权交给集中式 Controller，Controller 通过 OpenFlow 协议控制交换机 Flow Table，为特定负载计算路径并定义转发行为。 | `8-云计算网络-2026.pdf` p41-p42 |
| SDN 发展历程 | SDN 从 OpenFlow 代表的软件层控制转发分离，发展到广义 SDN 和数据中心骨干网实践，例如 Google B4，再进一步走向 P4 数据面可编程与软硬件融合的完全可编程网络。 | `8-云计算网络-2026.pdf` p43, p51-p53 |
| Overlay 虚拟网络 | Overlay 在物理网络上叠加一个可独立配置和管理的虚拟网络。虚拟机通过虚拟网卡连接到虚拟网络，虚拟网络再用隧道技术在物理网络中传输数据。它解决虚拟机迁移、租户隔离、同租户局域网一致性等问题。 | `8-云计算网络-2026.pdf` p48-p49 |
| P4 可编程网络 | P4 是面向网络数据面的专用语言，目标是让开发者自定义可编程交换芯片的转发逻辑。它解决 OpenFlow 编程能力不足、受限于固定硬件功能的问题，是从控制面可编程走向数据面可编程的重要阶段。 | `8-云计算网络-2026.pdf` p51-p52 |
| 基于软硬件融合的完全可编程网络 | SDN 可分三阶段：2010-2020 年 OpenFlow 分离控制面和数据面；2015-2025 年 P4/FPGA/ASIC 实现数据面可编程；2020-2030 年展望网卡、交换机、协议栈均可编程，使整个网络成为可编程平台。 | `8-云计算网络-2026.pdf` p53 |
| 云数据中心网络架构需求 | 云数据中心网络要求低成本、高可扩展性、低配置开销、健壮性、节能和一定灵活性。传统树形网络简单但扩展和容错不足，改进方向包括 FatTree、VL2、递归层次网络、光交换网络、无线数据中心网络等。 | `8-云计算网络-2026.pdf` p27-p38 |
| 数据中心节能 | 数据中心高能耗来自硬件规模扩大、高性能设备功耗、虚拟化和冗余带来的额外开销、制冷和供电系统消耗。节能措施包括高效处理器和存储、液冷/刀片服务器、智能资源调度、配电系统节能、空调系统节能、集装箱数据中心、DPM/DVFS、新能源应用等。 | `9-云数据中心-2026.pdf` p13, p17-p30 |

## 8. 云计算安全

| 重点 | 解答 | 来源 |

| 云场景下的安全维度 | 课程从四类问题分析云安全：数据存储与计算安全、虚拟化安全、网络安全、访问控制安全。移动云白皮书进一步从用户安全、云平台安全、安全合规保障，以及安全管理、安全运营构建“三横两纵”安全架构。 | `11-云计算安全-2026.pdf` p3, p17 |
| 数据存储与计算安全问题 | 数据是云计算关键资产，存到第三方云端会带来存储、计算、访问、合规和可用性隐患。解决思路包括使用可信数据存储与计算环境、遵守安全最佳实践、利用云平台安全能力、多地域多可用区或混合云策略、数据加密、密钥管理、敏感数据保护和数据库审计。 | `11-云计算安全-2026.pdf` p4-p6, p20 |
| 虚拟化安全问题 | 虚拟化解耦计算资源和硬件资源，使资源灵活分配与隔离，但虚拟机/容器逃逸成为典型威胁。解决思路包括及时修复漏洞、加强宿主机与 Hypervisor 安全、强化多租户隔离、使用容器安全扫描与逃逸检测、制定容器行为白名单。 | `11-云计算安全-2026.pdf` p7-p8, p19, p24 |
| 网络安全问题 | 云上服务暴露在公网，面临 DDoS、Web 攻击、网络边界暴露、流量劫持和信息泄露等风险。解决思路包括 VPC/SDN 构建独立网络空间、ACL 和安全组、专线/VPN、下一代防火墙、抗 DDoS、态势感知、WAF、漏洞扫描等。 | `11-云计算安全-2026.pdf` p9, p19, p21-p22 |
| 访问控制安全问题 | 访问控制始终是 IT 安全核心。公有云多租户和更广泛攻击面要求更好的账号、权限、认证、审计实践。解决思路包括最小授权、责任匹配、双因素认证、账号生命周期管理、堡垒机访问、日志审计、重要操作审批和安全组配置。 | `11-云计算安全-2026.pdf` p10, p23, p25 |
| 安全责任共担 | 云安全由云服务商和云服务客户共同承担。云服务商负责基础设施层和平台安全，客户负责数据管理、资产分类、权限分配、操作系统补丁、应用软件安全和安全组/防火墙等配置。IaaS 场景中客户承担的配置和管理责任更多。 | `11-云计算安全-2026.pdf` p31-p35 |
| 安全运营 | 安全运营应覆盖事前、事中、事后：事前降低脆弱性风险，事中监测、分析、响应，事后复盘沉淀和体系优化。平台技术上可结合 NDR、EDR、SIEM、SOAR、安全大数据和自动化响应。 | `11-云计算安全-2026.pdf` p26-p29 |
