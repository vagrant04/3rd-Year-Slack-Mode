## 🎯 核心知识点

### SOLID原则 (前5个)
1. **S** - Single Responsibility Principle (单一职责原则)
   - 一个类只负责一个功能领域中的职责
   - 高内聚、低耦合的体现

2. **O** - Open-Closed Principle (开闭原则) 🔥
   - **最重要的设计原则**
   - 对扩展开放，对修改关闭
   - 通过抽象化实现

3. **L** - Liskov Substitution Principle (里氏代换原则)
   - 基类能出现的地方，子类一定能出现
   - 是实现开闭原则的重要方式

4. **I** - Interface Segregation Principle (接口隔离原则)
   - 使用多个专门接口，而非单一总接口
   - 客户端不应该依赖它不需要的接口

5. **D** - Dependency Inversion Principle (依赖倒转原则) 🔥
   - **面向对象设计的主要手段**
   - 要针对接口编程，不要针对实现编程
   - 高层模块和低层模块都依赖于抽象

### 其他重要原则
6. **CRP** - Composite Reuse Principle (合成复用原则)
   - 组合/聚合优于继承
   - 提高灵活性，降低耦合度

7. **LoD** - Law of Demeter (迪米特法则)
   - 最少知识原则
   - 只与直接朋友通信

## 🗺️ 原则间的关系

```
           【目标】开闭原则 (OCP)
                    ↑
        ┌───────────┼───────────┐
        │           │           │
    【基础】    【指导】     【实现手段】
   SRP + EVP      LoD      DIP + CRP + LSP + ISP
```

- **目标**: 开闭原则 - 最终要达到的设计目标
- **指导**: 迪米特法则 - 设计过程的指导思想
- **基础**: 单一职责原则 + 可变性封装原则
- **实现**: 依赖倒转、合成复用、里氏代换、接口隔离

### 常见题型
1. **名词解释**: 解释某个设计原则
2. **判断分析**: 判断某个设计是否违反了某原则
3. **设计题**: 根据需求，应用设计原则进行类图设计
4. **重构题**: 给出一个违反原则的设计，要求重构

### 易混淆点 ⚠️
- **里氏代换 vs 依赖倒转**:
  - 里氏代换: 子类要能替换父类 (继承的规则)
  - 依赖倒转: 要依赖抽象而非具体 (编程的方向)
- **单一职责 vs 接口隔离**:
  - 单一职责: 一个类只负责一个职责 (类的粒度)
  - 接口隔离: 接口要小而专一 (接口的粒度)
- **组合 vs 聚合**:
  - 组合: 强拥有关系 (整体与部分生命周期一致)
  - 聚合: 弱拥有关系 (整体与部分生命周期独立)
