## 📋 课件概览

这是软件系统设计课程的第一讲，系统地介绍了面向对象设计的7个核心原则。课件通过大量UML类图和重构实例，展示了如何从违反原则的糟糕设计演化到符合原则的优秀设计。

### 🎯 学习目标

- 理解面向对象设计原则的必要性（可维护性、可复用性）
- 掌握7大设计原则的定义、分析和应用
- 能够识别违反设计原则的代码坏味道
- 掌握使用设计原则进行代码重构的方法
- 理解7个原则之间的层次关系

### 第二部分：7大设计原则（第11-57页）

#### 1. 单一职责原则 SRP（第11-17页）⭐⭐⭐⭐
- **定义**: 一个类只负责一个功能领域的职责
- **关键**: 高内聚、低耦合
- **实例**: Login类重构（第16-17页UML图）
- **页面**: [02-单一职责原则-SRP.md](./02-单一职责原则-SRP.md)

#### 2. 开闭原则 OCP（第18-22页）⭐⭐⭐⭐⭐
- **定义**: 对扩展开放，对修改关闭
- **关键**: 抽象化 + 可变性封装
- **实例**: 按钮系统重构（第19、22页UML图）
- **页面**: [03-开闭原则-OCP.md](./03-开闭原则-OCP.md)

#### 3. 里氏代换原则 LSP（第23-27页）⭐⭐⭐⭐
- **定义**: 子类对象可以透明地替换父类对象
- **关键**: 基类引用指向子类对象
- **实例**: 加密系统设计（第27页UML图）
- **页面**: [04-里氏代换原则-LSP.md](./04-里氏代换原则-LSP.md)

#### 4. 依赖倒转原则 DIP（第28-37页）⭐⭐⭐⭐⭐
- **定义**: 依赖抽象，不依赖具体类
- **关键**: 针对接口编程
- **实例**: 数据转换系统（第35页UML图）
- **页面**: [05-依赖倒转原则-DIP.md](./05-依赖倒转原则-DIP.md)

#### 5. 接口隔离原则 ISP（第38-43页）⭐⭐
- **定义**: 使用多个专门的接口，不使用单一总接口
- **关键**: 接口拆分、角色隔离
- **实例**: 胖接口拆分（第39-40页UML图）
- **页面**: [06-接口隔离原则-ISP.md](./06-接口隔离原则-ISP.md)

#### 6. 合成复用原则 CRP（第44-50页）⭐⭐⭐⭐
- **定义**: 优先使用组合/聚合，少用继承
- **关键**: 黑箱复用 vs 白箱复用
- **实例**: DAO类重构（第45、47页UML图）
- **页面**: [07-合成复用原则-CRP.md](./07-合成复用原则-CRP.md)

#### 7. 迪米特法则 LoD（第51-57页）⭐⭐⭐
- **定义**: 最少知识原则，只与朋友通信
- **关键**: 降低耦合、信息隐藏
- **实例**: Form-DAO中介者模式（第54、56页UML图）
- **页面**: [08-迪米特法则-LoD.md](./08-迪米特法则-LoD.md)

## 🔑 核心知识点

### 重要性排序（⭐越多越重要）
1. **开闭原则 OCP** ⭐⭐⭐⭐⭐ - 面向对象设计的**终极目标**
2. **依赖倒转原则 DIP** ⭐⭐⭐⭐⭐ - 实现OCP的**主要手段**
3. **单一职责原则 SRP** ⭐⭐⭐⭐ - 设计的**基础**
4. **里氏代换原则 LSP** ⭐⭐⭐⭐ - OCP的**重要实现方式**
5. **合成复用原则 CRP** ⭐⭐⭐⭐ - 复用的**首选方式**
6. **迪米特法则 LoD** ⭐⭐⭐ - 设计的**指导原则**
7. **接口隔离原则 ISP** ⭐⭐ - 接口设计的**细化要求**

### 原则之间的关系（第59页总结）
```
目标层：开闭原则（OCP）
   ↓
指导层：迪米特法则（LoD）+ 可变性封装原则（EVP）
   ↓
基础层：单一职责原则（SRP）
   ↓
实现层：依赖倒转原则（DIP）+ 合成复用原则（CRP）
        里氏代换原则（LSP）+ 接口隔离原则（ISP）
```

## 🎯 考试重点

### 必考知识点 ⚠️

#### 1. 原则定义（必背）
- **开闭原则**: 对扩展开放，对修改关闭
- **依赖倒转原则**: 依赖抽象，不依赖具体；针对接口编程
- **单一职责原则**: 一个类只负责一个功能领域的职责
- **里氏代换原则**: 子类对象可以透明地替换父类对象

#### 2. 原则关系（综合题常考）
- 开闭原则是**目标**
- 依赖倒转原则是实现开闭原则的**主要手段**
- 里氏代换原则是实现开闭原则的**重要方式之一**
- 单一职责原则是**基础**

#### 3. UML图识别与改进（实践题）
- 给出违反某原则的UML图，要求：
  - 识别违反了哪个原则
  - 指出问题所在
  - 画出重构后的UML图
- 常考原则：OCP、DIP、CRP

#### 4. 代码重构（编程题）
- 给出违反原则的代码，要求重构
- 常考场景：
  - if-else分支 → 策略模式（OCP）
  - 继承复用 → 组合复用（CRP）
  - 具体类依赖 → 抽象类依赖（DIP）

#### 5. 案例分析（论述题）
- Stack extends Vector的设计问题（第55页思考题）
- 什么情况下可以使用继承？
- 如何判断是否违反里氏代换原则？

### 易混淆点 💡

#### 1. LSP vs DIP
- **LSP**: 强调子类可以替换父类（继承关系的正确使用）
- **DIP**: 强调依赖抽象而非具体（抽象化设计）
- **联系**: 第27页的例子同时违反了LSP和DIP

#### 2. OCP vs EVP
- **OCP**: 对扩展开放，对修改关闭（目标）
- **EVP**: 封装可变因素（手段）
- **关系**: EVP是实现OCP的具体描述

#### 3. 继承 vs 组合
- **继承**: 白箱复用，编译时确定，耦合度高
- **组合**: 黑箱复用，运行时确定，耦合度低
- **原则**: CRP要求优先使用组合

#### 4. 接口 vs 抽象类
- **ISP的"接口"**: 指方法的集合（可以是接口或抽象类）
- **DIP的"抽象"**: 包括接口和抽象类
- **区别**: ISP关注接口大小，DIP关注依赖方向
