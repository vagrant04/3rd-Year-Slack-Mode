## 4. 综合设计题答题模板

### 4.1 通用架构设计题模板

```text
1. 识别业务目标和涉众。
2. 识别 ASR：
   - 功能需求
   - 质量需求
   - 约束
3. 写关键质量属性场景：
   Source / Stimulus / Environment / Artifact / Response / Measure
4. 选择架构模式和战术：
   - 为什么适合
   - 解决什么问题
   - 牺牲什么
5. 画视图：
   - C&C 视图或 4+1 视图
   - 必要时画部署视图
6. 说明设计决策：
   - 职责分配
   - 协调模型
   - 数据模型
   - 资源管理
   - 绑定时间
   - 技术选型
7. 说明风险、敏感点、权衡点。
```

### 4.3 微服务设计题模板

```text
1. 为什么适合微服务：
   - 业务模块独立
   - 团队可并行开发
   - 不同模块负载差异大
   - 需要独立部署和扩缩
   - 需要故障隔离

2. 服务拆分：
   - 按业务能力拆分，而不是按技术层拆分
   - 用户服务
   - 订单服务
   - 支付服务
   - 商品/商家服务
   - 配送服务
   - 通知服务

3. 通信方式：
   - 外部通过 API Gateway
   - 内部同步 REST/RPC
   - 异步事件用消息队列
   - 可结合事件驱动降低服务之间的同步耦合

4. 数据管理：
   - 每服务独立数据库
   - 跨服务一致性用 Saga 或事件最终一致

5. 质量属性：
   - 可修改性：服务独立演进
   - 可伸缩性：热点服务独立扩容
   - 可用性：熔断、限流、降级
   - 性能：缓存、异步化、负载均衡
   - 安全性：网关认证、服务间鉴权

6. 取舍：
   - 增加分布式复杂度
   - 数据一致性更难
   - 运维和监控成本更高

7. 部署运维：
   - 容器化部署
   - 服务注册与健康检查
   - 日志、监控、链路追踪
   - 熔断、限流、降级

8. 可画六边形架构：
   - 领域核心在中心
   - 外部 UI、数据库、消息队列、第三方服务通过端口/适配器接入
```

### 4.4 设计模式题模板

```text
1. 指出使用的设计模式。
2. 说明模式意图。
3. 映射角色：
   - Context/Subject/Observer/Command/Invoker/Receiver/...
4. 画类图或写文字结构。
5. 写关键代码或伪代码。
6. 说明体现的设计原则：
   - OCP
   - DIP
   - SRP
   - CRP
7. 说明优缺点和适用场景。
```

### 4.5 多模式联合使用模板

```text
1. 先识别变化点：
   - 对象如何创建？ -> 创建型模式
   - 对象如何组织成结构？ -> 结构型模式
   - 行为如何变化或协作？ -> 行为型模式

2. 组合模式示例：
   - Abstract Factory / Factory Method：创建一组相关对象
   - Composite / Adapter / Facade：组织对象结构或统一接口
   - Strategy / State / Command / Observer：封装行为变化或对象协作

3. 解释为什么组合：
   - 每个模式解决一个子问题
   - 组合后满足 OCP/DIP/SRP/CRP
   - 说明带来的复杂度或依赖

4. 画图顺序：
   - 先画核心业务类
   - 再画接口/抽象类
   - 最后画模式协作关系
```
