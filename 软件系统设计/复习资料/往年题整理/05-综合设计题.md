## 设计题1：策略模式 — 飞行模拟软件

**【2018】** 设计一个飞行模拟软件，要求能模拟多种飞机的特性。为了在将来支持更多飞机种类，要求使用策略模式。画出架构图和类图。

> 出处：[押题汇总#p2](../往年题/2015、2017、2018、2019押题、2019.pdf#page=2)（2018题11）

### 标准答案

#### 类图设计：

```
┌─────────────────────┐
│    <<interface>>     │
│    FlyBehavior      │
├─────────────────────┤
│ + fly(): void       │
└──────────┬──────────┘
           │ implements
    ┌──────┼──────────┐
    │      │          │
┌───┴───┐ ┌┴────────┐ ┌┴──────────┐
│SubSonic│ │SuperSonic│ │ Helicopter │
│FlyBehav│ │FlyBehav │ │ FlyBehav  │
├────────┤ ├─────────┤ ├───────────┤
│+fly()  │ │+fly()   │ │+fly()     │
└────────┘ └─────────┘ └───────────┘

┌──────────────────────────┐
│      Aircraft            │
├──────────────────────────┤
│ - flyBehavior: FlyBehavior│
│ - name: String           │
├──────────────────────────┤
│ + performFly(): void     │
│ + setFlyBehavior(): void │
└──────────┬───────────────┘
           │ extends
    ┌──────┼──────┐
    │      │      │
┌───┴──┐ ┌┴────┐ ┌┴──────┐
│Fighter│ │Bomber│ │Chopper│
└───────┘ └─────┘ └───────┘
```

#### 关键代码：

```java
// 策略接口
public interface FlyBehavior {
    void fly();
}

// 具体策略
public class SuperSonicFly implements FlyBehavior {
    public void fly() { /* 超音速飞行 */ }
}

// 上下文
public abstract class Aircraft {
    private FlyBehavior flyBehavior;
    
    public void performFly() {
        flyBehavior.fly();
    }
    
    public void setFlyBehavior(FlyBehavior fb) {
        this.flyBehavior = fb;
    }
}
```

#### 体现的设计原则：
- **OCP**：新增飞机类型只需创建新的FlyBehavior实现类
- **DIP**：Aircraft依赖FlyBehavior接口，不依赖具体实现
- **SRP**：飞行算法封装在独立策略类中

4. 系统需要避免使用难以维护的多重条件选择语句

## 设计题3：观察者模式+组合模式 — 游戏角色通知

**【2019】** 一个游戏，有几种人类角色（骑士、骑兵、步兵），持有不同武器，拥有fight方法；有一个非人类角色巨魔，可以持有武器但攻击方法不同(beat)。现在希望让巨魔和其他人类角色一起进行游戏，并且要求有角色死亡时其他活着的角色要收到通知。运用设计模式进行设计。

> 出处：[Exam0-往年考试.pdf#p11](../往年题/Exam0-往年考试.pdf#page=11)

### 标准答案

使用**观察者模式**实现死亡通知 + **策略模式**处理不同攻击方式：

```
┌────────────────┐       ┌──────────────────┐
│ <<interface>>  │       │  <<interface>>   │
│ GameObserver   │       │ AttackBehavior   │
├────────────────┤       ├──────────────────┤
│+onDeath(char)  │       │+attack(): void   │
└───────┬────────┘       └────────┬─────────┘
        │                         │
┌───────┴────────┐       ┌───────┴──────┐
│   Character    │◇──────│ FightAttack  │
├────────────────┤       │ BeatAttack   │
│-weapon         │       └──────────────┘
│-alive: boolean │
│-observers: List│
├────────────────┤
│+die(): void    │  ← 调用notifyAll
│+notifyAll()    │
│+attack(): void │  ← 委托给AttackBehavior
└───────┬────────┘
        │extends
   ┌────┼────┐
   │    │    │
Knight Cavalry Troll
```

当角色die()时，通知所有注册的observer（其他存活角色）。

## 设计题4：组合模式+观察者模式 — 大学通知系统

**【2021】【2022】** 一个大学由若干个系组成，每个学生和老师都属于某一个系，由此形成一个树状结构。大学管理员想给一些部门或一些个人发送通知。

> 出处：[2021痛苦回忆#p1](../往年题/2021%20痛苦回忆.pdf#page=1)、[2022试卷#p2](../往年题/软统2022试卷.pdf#page=2)

### 标准答案

使用**组合模式**构建树状结构 + **观察者模式**实现通知：

```
┌──────────────────────┐
│    <<interface>>      │
│    OrganizationUnit   │
├──────────────────────┤
│ + notify(msg): void   │
│ + getName(): String   │
└──────────┬───────────┘
           │
    ┌──────┼──────────┐
    │                  │
┌───┴──────────┐  ┌───┴──────────┐
│  Department  │  │   Person     │
│  (Composite) │  │   (Leaf)     │
├──────────────┤  ├──────────────┤
│-children:List│  │-name: String │
├──────────────┤  ├──────────────┤
│+add(unit)    │  │+notify(msg)  │
│+remove(unit) │  └──────────────┘
│+notify(msg)  │ ← 递归调用children.notify
└──────────────┘
```

```java
public interface OrganizationUnit {
    void notify(String message);
}

public class Department implements OrganizationUnit {
    private List<OrganizationUnit> children = new ArrayList<>();
    
    public void add(OrganizationUnit unit) { children.add(unit); }
    
    public void notify(String message) {
        for (OrganizationUnit child : children) {
            child.notify(message);
        }
    }
}

public class Person implements OrganizationUnit {
    private String name;
    
    public void notify(String message) {
        System.out.println(name + " received: " + message);
    }
}
```

## 设计题5：组合命令（宏命令）

**【2021】** 什么是组合命令（又称宏命令）？写出大概的组合命令类的代码。

> 出处：[2021痛苦回忆#p1](../往年题/2021%20痛苦回忆.pdf#page=1)

### 标准答案

**组合命令/宏命令**：将多个命令组合成一个命令执行，是组合模式在命令模式中的应用。

```java
public class MacroCommand implements Command {
    private List<Command> commands = new ArrayList<>();
    
    public void add(Command cmd) { commands.add(cmd); }
    public void remove(Command cmd) { commands.remove(cmd); }
    
    @Override
    public void execute() {
        for (Command cmd : commands) {
            cmd.execute();
        }
    }
    
    @Override
    public void undo() {
        // 逆序撤销
        for (int i = commands.size()-1; i >= 0; i--) {
            commands.get(i).undo();
        }
    }
}
```

## 设计题6：管道-过滤器模式 — 文本处理

**【2021】** 设计一个基于管道-过滤器模式的、输入文本文件、输出排序后的无重复的单词列表的程序。

> 出处：[2021痛苦回忆#p1](../往年题/2021%20痛苦回忆.pdf#page=1)

### 标准答案

#### 组件和连接器图：

```
[Input] → |FileReader| → pipe → |Splitter| → pipe → |DuplicateRemover| → pipe → |Sorter| → [Output]
```

#### 类图：

```
┌─────────────────┐
│  <<interface>>  │
│     Filter      │
├─────────────────┤
│+process(in):out │
└────────┬────────┘
         │ implements
    ┌────┼────────┐─────────┐
    │    │        │         │
┌───┴──┐┌┴──────┐┌┴───────┐┌┴──────┐
│FileRd││Split  ││DupRmv  ││Sorter │
└──────┘└───────┘└────────┘└───────┘

┌─────────────────┐
│     Pipe        │
├─────────────────┤
│-data: String    │
│+read(): String  │
│+write(s): void  │
└─────────────────┘

┌─────────────────────┐
│    Pipeline         │
├─────────────────────┤
│-filters: List<Filter>│
│+addFilter(f): void  │
│+execute(): void     │
└─────────────────────┘
```

#### Java实现（核心）：

```java
public interface Filter {
    String process(String input);
}

public class Splitter implements Filter {
    public String process(String input) {
        return String.join("\n", input.split("\\s+"));
    }
}

public class DuplicateRemover implements Filter {
    public String process(String input) {
        Set<String> set = new LinkedHashSet<>(Arrays.asList(input.split("\n")));
        return String.join("\n", set);
    }
}

public class Sorter implements Filter {
    public String process(String input) {
        List<String> words = new ArrayList<>(Arrays.asList(input.split("\n")));
        Collections.sort(words);
        return String.join("\n", words);
    }
}
```

## 设计题7：分布式缓存同步（观察者模式应用）

**【2015】【2019】【2022】反复出现** Distributed Cache Updates — 使用Observer模式解决缓存同步

> 出处：[2015真题第3页](../往年题/2015/3.jpg)、[2022试卷#p2](../往年题/软统2022试卷.pdf#page=2)、[Exam0-往年考试.pdf#p12](../往年题/Exam0-往年考试.pdf#page=12)

### 题目描述

一个在线客户服务系统，N台服务器集群，每台服务器有缓存。客户端请求导致缓存更新时：
- REQ1: 变更提交到数据库
- REQ2: 所有其他缓存必须失效并从数据库重新加载

当前设计无法满足REQ2，需要应用架构模式和策略。

### 标准答案

**(a) 识别额外组件（5分）**：

需要新增 **CacheCoordinator（缓存协调器）** 组件：
- 功能1：监听所有Cache的状态变更事件
- 功能2：当一个Cache变更时，通知其他所有Cache失效
- 功能3：触发其他Cache从Database重新加载

**(b) Observer模式角色映射（5分）**：

| Observer角色 | 映射到的组件 |
|-------------|-----------|
| Subject（被观察者）| CacheCoordinator |
| Observer（观察者）| Cache 1, Cache 2, ... Cache N |
| attach/detach | Server启动/关闭时注册/注销Cache |
| notifyObservers | 当某个Cache变更时，CacheCoordinator通知所有其他Cache |

**(c) 序列图**：

```
Client → Server1 → Cache1: update data
Cache1 → Database: commit changes (REQ1)
Cache1 → CacheCoordinator: notifyChange()
CacheCoordinator → Cache2: invalidate()
CacheCoordinator → Cache3: invalidate()
CacheCoordinator → CacheN: invalidate()
Cache2 → Database: reload()
Cache3 → Database: reload()
```

**(d) 异构服务器的Connector/Web Services解决方案（5分）**：

使用 **Web Services** 方式：
- 为所有Cache定义统一的WSDL接口（invalidate、reload操作）
- CacheCoordinator通过标准的SOAP/REST协议调用各Cache
- 无论Cache底层是Java RMI、HTTP JSP还是SOAP，都统一暴露为Web Service接口
- 这样解耦了协议差异，CacheCoordinator只需面向统一接口编程

或使用 **Connector** 方式：
- 为每种协议创建适配器（Adapter）：RMI Adapter、JSP Adapter、SOAP Adapter
- 所有Adapter实现统一的CacheConnector接口
- CacheCoordinator通过CacheConnector接口操作，不关心具体协议

## 设计题8：Multi-instance模式

**【2022】** Design a Multi-instance pattern. Make sure that the number of objects of a class in the system cannot exceed a given constant n. Write code to implement a Multi-instance class.

> 出处：[2022试卷#p2](../往年题/软统2022试卷.pdf#page=2)

### 标准答案

```java
public class MultiInstance {
    private static final int MAX_COUNT = 3; // 常量n
    private static List<MultiInstance> instances = new ArrayList<>();
    
    private MultiInstance() {} // 私有构造
    
    public static synchronized MultiInstance getInstance() {
        if (instances.size() < MAX_COUNT) {
            MultiInstance instance = new MultiInstance();
            instances.add(instance);
            return instance;
        }
        // 循环分配已有实例
        return instances.get((int)(Math.random() * MAX_COUNT));
    }
    
    public static int getInstanceCount() {
        return instances.size();
    }
}
```

本质是**单例模式的推广**（从最多1个扩展到最多n个）。

## 设计题9：通知系统设计（多渠道+条件判断）

**【2025】** 设计通知系统，通过多个通知渠道通知利益相关者，不同渠道要满足运行时条件才能使用，系统要避免产生用不到的信息。

> 出处：[2025期末](../往年题/软统25期末-不完全准确.jpeg)

### 标准答案

使用**观察者模式** + **策略模式** + **装饰者/条件过滤**：

```
┌────────────────────┐     ┌──────────────────┐
│   <<interface>>    │     │  <<interface>>   │
│   NotifyChannel    │     │  ChannelCondition│
├────────────────────┤     ├──────────────────┤
│+canSend(): boolean │     │+isMet(): boolean │
│+send(msg): void   │     └──────────────────┘
└────────┬───────────┘
         │
    ┌────┼────┐────────┐
    │    │    │        │
  Email  SMS  Push   WeChat

┌─────────────────────────┐
│    NotificationService  │
├─────────────────────────┤
│-channels: List<Channel> │
│-stakeholders: List      │
├─────────────────────────┤
│+notify(msg): void       │ ← 遍历channels，检查canSend()后发送
│+addChannel(): void      │
└─────────────────────────┘
```

核心逻辑：notify时遍历所有channel，仅在`canSend()`为true时才生成并发送消息，避免产生用不到的信息。

## 设计题10：外卖平台微服务设计

**【2025】** 外卖平台为什么适合使用微服务？微服务设计拆分的具体应用。

> 出处：[2025期末](../往年题/软统25期末-不完全准确.jpeg)

### 标准答案

**为什么适合微服务**：
1. 外卖平台业务模块独立：用户、商家、骑手、订单、支付各自独立演进
2. 流量特征不同：用户浏览高频、支付低频但关键，需独立扩缩
3. 团队规模大：不同团队负责不同模块，适合独立开发部署
4. 高可用要求：单个服务故障不应拖垮全系统（熔断隔离）

**微服务拆分示例**：

| 操作 | 微服务 | 对应关系 |
|------|--------|---------|
| 用户注册/登录 | 用户服务 User Service | 管理用户信息、认证 |
| 浏览餐厅/菜单 | 商家服务 Merchant Service | 管理商家和菜品数据 |
| 下单 | 订单服务 Order Service | 订单创建、状态管理 |
| 支付 | 支付服务 Payment Service | 对接支付渠道 |
| 配送调度 | 配送服务 Delivery Service | 骑手调度、路径规划 |
| 消息推送 | 通知服务 Notification Service | 短信/Push通知 |

通过API Gateway统一入口，服务注册与发现实现服务间通信，熔断器保证容错。

> **关联资料**：[旧课件-微服务#p3](../../../旧课件/Lecture%2003%20-%20Microservices%20Patterns.pdf#page=3)；[笔记-系统架构#p65](../笔记/软件系统设计-系统架构.pdf#page=65) — 微服务架构
