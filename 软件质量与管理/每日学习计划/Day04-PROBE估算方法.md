## 一、估算的本质

- 估算是在**预测未来**，经常是错误的（误差巨大）
- 但估算过程**仍然有用**：管理不确定性、发现误解和不一致、建立对工作的一致理解
- **收益递减原则**：不应花太多时间在估算上

### 为什么可以用历史数据完成规模估算？
> 因为使用代理规模与实际程序规模之间的关系完成规模估算，**规模估算产生偏差的原因相对客观**，偏差可以用来修正新的估算结果。

### 为什么时间估算的偏差更复杂？
> 一方面和**规模**有关，另一方面跟**人的主观能动性**有关。因此时间估算偏差产生的原因可能是估算结果本身，这使得历史数据中时间偏差可参考价值不大。

---

## 二、PROBE 方法的基本原理（2020-mid 4分）

### 两个核心原理

```
1. 设立合理的代理作为精确度量和早期规划需要的度量之间的桥梁
2. 使用相对大小而非绝对大小
```

> **PROBE** = PROxy Based Estimation（基于代理的估算）

---

## 三、PROBE 方法的过程（2020-mid 4分，需画流程图）

```
        ┌────────────┐
        │  概要设计    │
        └──────┬─────┘
               ↓
    ┌─────────────────────┐
    │ 代理识别和代理规模(E) │
    └────┬───────────┬────┘
         ↓           ↓
┌──────────────┐ ┌──────────────┐
│估算并调整程序规模│ │估算并调整资源  │
└──────┬───────┘ └──────┬───────┘
       ↓                 ↓
┌──────────────┐ ┌──────────────┐
│ 计算预测区间   │ │ 计算预测区间   │
└──────────────┘ └──────────────┘
```

### 估算过程详解

1. **概要设计**：确认产品功能，明确所需的程序组件/模块
2. **代理识别和代理规模**：将组件/模块与之前缩写的程序序比较，估算规模，得到总规模
3. **估算并调整程序规模**（左路）：用线性回归方法
4. **估算并调整资源**（右路）：用线性回归方法
5. **计算预测区间**：给出置信区间

### 估算要点
- 尽可能划分详细一些
- 建立对结果的信息
- 依赖数据
- **估算关注的是过程而不是结果**

## 四、PROBE ABCD 方法（2020-mid 10分大题 必考！）

### 估算规模时的数据质量要求

| PROBE方法 | 数据要求 | 数据质量要求 | 计算方法 |
|----------|---------|-----------|---------|
| **A** | 3组或3组以上**代理规模(E)**与**实际程序规模**数据 | r≥0.7; s≤0.05; β0≤估算结果的25%; 0.5≤β1≤2 | 线性回归 |
| **B** | 3组或3组以上**计划程序规模**与**实际程序规模**数据 | r≥0.7; s≤0.05; β0≤估算结果的25%; 0.5≤β1≤2 | 线性回归 |
| **C** | 有历史数据 | 无质量要求 | **按比例调整** |
| **D** | 没有历史数据 | 无 | **猜测** |

### 估算时间时的数据质量要求

| PROBE方法 | 数据要求 | 数据质量要求 | 计算方法 |
|----------|---------|-----------|---------|
| **A** | 3组或3组以上**代理规模(E)**与**实际开发时间** | r≥0.7; s≤0.05; β0显著小于估算结果; β1≤0.5×(历史生产效率的倒数) | 线性回归 |
| **B** | 3组或3组以上**计划程序规模**与**实际开发时间** | r≥0.7; s≤0.05; β0显著小于估算结果; β1≤0.5×(历史生产效率的倒数) | 线性回归 |
| **C** | 有历史数据 | 无 | **按比例调整** |
| **D** | 没有历史数据 | 无 | **猜测** |

### 评分标准
> A、B 都是 **3分**，C和D 都是 **2分**

### 参数含义

| 参数 | 含义 |
|------|------|
| **r** | 相关性（两组数据之间互相关联的程度），PSP要求 **r ≥ 0.7** |
| **s** | 显著性（两组数据的相关关系出现的偶然性），PSP要求 **s ≤ 0.05** |
| **β0** | 回归截距 |
| **β1** | 回归斜率 |

## 五、为什么不使用生产效率数据？（2020-mid 2分）

> 在估算资源需求（例如人时）的时候，生产效率一般在**分母**上。考虑到个体软件工程师**生产效率波动**，容易导致估算偏差范围变大。

---

## 六、规模度量标准

选择度量方式的四个要求：
1. 必须反映开发成本
2. 必须精确
3. 必须能用**自动化方法**来统计
4. 必须有助于早期规划

### 规模度量方法对比（LOC vs FP）

| 方法 | 优点 | 缺点 |
|------|------|------|
| **LOC** | 是软件开发项目的生成品，容易进行计算 | 依赖程序设计语言(不同语言有偏差)；对代码量少但设计精巧的程序不利；不适合非过程语言；开发初期估算代码行数困难 |
| **FP** | 和程序设计语言无关；面向过程和非过程语言均适合；基于项目开发初期就可能得到的数据 | 计算基于主观而非客观数据 |

> 随着软件产业化分工，基于LOC的度量方式逐渐失去意义，而基于FP的度量方式显得更加符合要求。

---

## 七、线性回归方法要点

```
Plan Size = β0 + β1 × size(E)
Plan Time = β0 + β1 × time(E)
Range = t(p,df) × σ₁ × √(1 + 1/n + ...)
```

### 处理有限的历史数据

规模估算的四种方法（从简单到复杂）：
1. **简单方法**：VS=min, S=VS+M/2, M=median, L=M+VL/2, VL=max → 计算简单但不稳定
2. **正态分布法**：VS=M-2σ, S=M-σ, L=M+σ, VL=M+2σ → 相对稳定
3. **对数正态分布法**：先取对数，按正态分布法计算，再取反对数 → 符合直觉（大多数人写小程序多，大程序少）
4. **线性回归方法**：利用相关性进行预测

静态住宅 ISP 代理（Static Residential ISP Proxy）之所以在**跨境电商、广告投放、社交媒体运营、数据采集**等领域广泛使用，本质上是因为它结合了：

* **住宅IP的高信任度**
* **数据中心IP的稳定性和速度**

这两个看似矛盾的优点。

## 一、先理解什么是 ISP 代理

代理IP大致分为三类：

| 类型                              | IP来源            | 特点             |
| ------------------------------- | --------------- | -------------- |
| 数据中心代理（Datacenter Proxy）        | 云服务器、机房         | 快、便宜、容易被识别     |
| 住宅代理（Residential Proxy）         | 家庭宽带用户          | 真实用户IP，可信度高    |
| ISP代理（Static Residential Proxy） | ISP运营商分配，但托管在机房 | 同时具有住宅IP和机房稳定性 |

例如：

* 普通机房IP：

  * AWS
  * Azure
  * 阿里云

网站一看就知道：

> 这是服务器，不是真人。

---

而ISP代理可能显示为：

> Singapore Telecom
> Comcast
> Verizon

网站会认为：

> 这是一个普通家庭宽带用户。

但实际上它运行在服务器上。

---

## 二、为什么跨境电商喜欢用 ISP 代理

### 场景1：运营多个店铺账号

例如：

* Amazon
* eBay
* Etsy
* Shopee
* Lazada

这些平台会检查：

* IP地址
* 浏览器指纹
* Cookie
* 登录习惯

目的是防止：

* 批量注册
* 工作室养号
* 店铺关联

---

假设你有：

* 美国店铺A
* 美国店铺B
* 美国店铺C

如果都用同一个IP登录：

```
123.123.123.123
```

平台可能判断：

> 这些账号属于同一主体。

产生：

* 账号关联
* 风控
* 限流
* 封号

---

ISP代理可以做到：

店铺A：

```
美国住宅IP1
```

店铺B：

```
美国住宅IP2
```

店铺C：

```
美国住宅IP3
```

看起来像三个不同家庭用户。

---

### 场景2：查看本地市场价格

例如你在中国。

想看美国站 Amazon：

```
美国用户看到什么价格？
```

直接访问可能看到：

* 国际版页面
* 不完整库存
* 不同广告

---

使用美国ISP代理后：

网站认为：

> 这是美国本地用户。

可以获得：

* 本地价格
* 本地搜索结果
* 本地广告

## 四、为什么不用普通住宅代理？

住宅代理又分：

### 动态住宅代理

例如：

```
今天：
1.2.3.4

明天：
5.6.7.8

后天：
9.10.11.12
```

IP不断变化。

适合：

* 爬虫
* 数据采集

不适合：

* 长期养号
* 店铺运营

---

### 静态住宅ISP代理

例如：

```
账号A
↓
美国IP 73.x.x.x

连续使用半年
```

IP长期不变。

平台会认为：

> 这是同一个真实用户。

账号权重更稳定。

## 六、ISP代理最核心的价值

从网站风控系统角度看：

### 数据中心IP

```
可信度：低
稳定性：高
成本：低
```

---

### 住宅IP

```
可信度：高
稳定性：低
成本：高
```

---

### ISP代理

```
可信度：高
稳定性：高
成本：较高
```

因此成为：

* 跨境电商
* Facebook广告
* Google广告
* TikTok运营
* 社交媒体矩阵
* 品牌监测
* 价格监测
* SEO工具

最常见的代理类型之一。

---

不过需要注意一点：

**ISP代理并不能保证绕过平台规则。**

像 Amazon、Facebook、Google 等平台的风控远不只是看 IP，还会综合分析：

* 浏览器指纹
* Cookie
* 设备信息
* 登录行为
* 支付信息
* 收货地址
* 账号关系图谱

因此 ISP 代理只能解决“IP可信度和地理位置一致性”的问题，而不能保证避免账号关联或规避平台政策。对于合法的跨区域运营、测试和市场调研，它确实是一个比较稳定的网络基础设施选择。
