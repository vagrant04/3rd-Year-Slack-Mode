# Day 3：自主团队 + 知识工人领导力 + 项目计划框架

> 预计用时：30分钟 | 考频：★★★★★
> 考题来源：2013、2014、2015A、2015B、2016、2020-mid、2023（最高频考点之一）

---

## 一、软件开发的本质特点

1. 软件开发是一项既**复杂**又富有**创造性**的知识工作
2. 软件开发是一种**智力劳动**
3. 开发者是**智力劳动者**（知识工作者）

---

## 二、知识工人管理的第一准则

> **管理的第一准则就是：智力劳动者不能被管理，只能实现自我管理。**

知识工人的特点：
- ✅ 处理和讨论**非常抽象**的概念
- ✅ 把不同的部分(不可见)整合成一个可以工作的**正确的系统**
- ✅ **全身心地参与**
- ✅ 努力做出**卓越的工作**

---

## 三、自主团队的特点（最高频！2013-2020 几乎每年考）

### 六大特点（必背！每两点1分）

```
1. 自行定义项目的目标
2. 自行决定团队组成形式以及成员的角色
3. 自行决定项目的开发策略
4. 自行定义项目的开发过程
5. 自行制定项目的开发计划
6. 自行度量、管理和控制项目工作
```

### 为什么自主团队可以满足软件开发对团队的要求？

> 因为软件开发是智力活动，开发者是智力劳动者，管理的第一准则就是智力劳动者不能被管理，只能实现自我管理。自主团队通过让成员自行决定目标、策略、过程、计划等，实现了对智力劳动者的自我管理。

## 四、知识工人的领导力（2023年 考题：15分大题）

### Maslow 需求层次理论

```
       自我实现
      ─────────
       尊重需求
      ─────────
       社交需求
      ─────────
       安全需求
      ─────────
       生理需求
```

### Herzberg 双因素理论

| 因素类型 | 说明 | 举例 |
|---------|------|------|
| **保健因素** | 消除不满，但不能激励 | 工资、工作环境、人际关系 |
| **激励因素** | 真正产生激励作用 | 成就感、认可、责任、成长 |

### McGregor X/Y理论

| 理论 | 假设 | 管理方式 |
|------|------|----------|
| **X理论** | 人天生懒惰、逃避责任、需要强制控制 | 严格监督、惩罚驱动 |
| **Y理论** | 人天生有工作动力、能自我管理、追求责任 | 授权、信任、创造环境 |

### 期望理论（课上讲过的例子）

> Motivation = Valence × Expectancy(Instrumentality)
> 即：**激发力量 = 价值(效价) × 完成目标的可能性**

⚠️ 课上问题："第一次开会时，为什么要构建高质量软件不是一个恰当的计划？"
→ 答：用期望理论解释。构建高质量软件目标太远大，完成可能性(Expectancy)很低，所以激发力量不足。

## 五、项目计划框架（2013、2014、2015A、2015B、2016 高频）

### 制定让人无法拒绝的计划

**基本步骤**：
1. **制定任务计划和日程计划**：描述项目所有的任务清单、任务之间的先后顺序、每个任务所需时间资源；然后描述各任务在日历上的安排（哪天开始，哪天结束）
2. **制定资源计划**
3. 这种日程计划的关键是必须用**正推的方式**来制订项目计划

### 通用计划框架（必背流程图内容）

```
客户需求 → 定义需求 → 概要设计 ─┐
                                  ├──PROBE估算方法──→ 规模历史数据
客户 ←── 规模估算 ←────────────┘              → 生产效率历史数据
         ↓                                      → 团队资源水平
      资源估算 ──────────────────────────→ 管理层
         ↓
      日程计划
         ↓
      开发产品 → 规模、资源、日程数据收集 → 过程分析 → 跟踪报告
         ↓
      交付产品
```

**哪些步骤必须人为干预？**
1. 定义需求
2. 概要设计（划分由人为开始，规模划分好之后估算是自动产生的）
3. 日程计划

**PROBE方法在此框架中充当什么角色？**
→ 虚线框即为PROBE，用来完成**规模和资源的评估**

## 六、需求开发的完整过程（2015 考题）

```
需求获取 → 需求汇总 → 需求验证 → 需求文档制作
```

### 客户需求 vs 产品需求

| 概念 | 定义 |
|------|------|
| **客户需求** | 客户的**期望**。客户在实际工作中碰到一些具体问题，希望通过某个东西来帮忙解决。可能很简单也可能很复杂，可能很清晰也可能很模糊 |
| **产品需求** | 开发团队所提供的**解决方案**。即针对客户需求，开发团队设计出一个可以帮助客户解决工作中碰到的问题的方案 |
